# Project Onboarding

当用户说"这个项目是干什么的"、"帮我看懂这个仓库"时，按这个流程走。

## 步骤

1. 跑 `list_files` 看顶层结构，再读 README（没有 README 就读
   `pyproject.toml` / `package.json` / `Makefile` 猜用途）。
2. 跑 `glob_files` 看源码分布（比如 `src/**/*.py`），挑 2-3 个
   核心文件读一遍：入口文件、核心循环、配置。
3. 输出一份结构说明，包含：
   - 一句话：这个项目是干什么的；
   - 怎么跑：安装、配置、启动命令；
   - 目录地图：每个目录是干什么的；
   - 关键流程：一次典型请求/任务是怎么流转的；
   - 改哪里：想加功能先看哪几个文件。
4. 不确定的地方写"不确定"，不要编。超过 3 个不确定就先问用户。

## 注意

- 只读、不写。不要顺手"优化"人家的代码。
- 输出控制在 30 行以内，先给结论再给细节。
