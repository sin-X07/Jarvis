# Code Review

当用户说"评审一下这次改动"、"review 一下"时，按这个流程走。

## 步骤

1. 跑 `git_status` 看改了哪些文件，再跑 `git_diff` 看具体改动。
2. 逐文件检查下面几类问题：
   - 正确性：逻辑错没错，边界条件（空值、越界、异常）处理了没；
   - 安全：有没有把 key、密码写进代码，有没有命令注入、路径穿越；
   - 可读性：命名清不清楚，有没有该抽出来的重复代码；
   - 测试：改动有没有对应的测试，测试跑没跑过。
3. 按"必须改 / 建议改 / 只是提醒"三档列出来，每条写清文件和行号，
   再给一句怎么改。不要只说"这里有问题"不给改法。
4. 最后问用户：要不要我直接按"必须改"那几项修掉。

## 注意

- 只评审 diff 里的改动，不要顺带重构整个文件。
- 不确定的问题标"不确定"，不要硬编。
