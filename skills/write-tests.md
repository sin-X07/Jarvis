# Write Tests

当用户说"给这个功能写测试"、"补测试"时，按这个流程走。

## 步骤

1. 先读现有的 `test_*.py`，看测试风格：每个文件一个主题，每个
   test_ 函数验证一件事，成功打印 `[OK] ...`，入口是
   `if __name__ == "__main__":` 逐个调用。
2. 测试要离线：不用真 key、不联网。模型用 FakeClient 冒充，
   网页用本地 http.server 冒充，文件用临时目录隔离。
3. 每个新功能至少覆盖：正常情况、边界情况、失败情况（比如
   参数错误、文件不存在、超时）。
4. 写完立刻跑：`python test_xxx.py`，全绿才算完；再跑
   `python run_tests.py` 确认没弄坏别的测试。
5. 测试里不要写真实 key、真实路径（不要碰 `~/.jarvis` 之外的
   真实文件），临时文件用 `tempfile.mkdtemp()`。

## 注意

- 测试失败先看是不是测试本身写错了，再看是不是功能错了，
  不要为了让测试通过去改功能。
- 每个测试函数只断言一件事，失败信息里写清楚期望值和实际值。
